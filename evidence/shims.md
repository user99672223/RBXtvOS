## Missing but lazily bound (deliberately not shimmed)

dyld does not resolve a lazy binding at launch, so these cannot stop
the app loading; it binds them on first call. Shimming them would add
behaviour the iOS build does not have, so each is recorded with the
reason it is left alone.


### <flat-namespace>

`<flat-namespace>`

- **Imported by:** `Frameworks/RobloxLib.framework/RobloxLib`
- **Missing on device — evidence:** Not exported by anything in the bundle, anywhere in the device cache (2,709 images), or in iOS SDK 26.2. Bound CLASS.LAZY with the flat-namespace (dynamic lookup) ordinal.
- **Decision:** NO SHIM
- **Reason:** Lazy bindings are not resolved at launch, so these cannot stop the app loading; dyld binds them on first call. They are equally unresolved in Roblox's own iOS build, which means matching iOS behaviour is to leave them alone. They are MIG message-validation functions inside Roblox's crash reporter, and inventing semantics for them would change crash handling in a way iOS does not. If the log ever shows them being reached, that is new information and is worth revisiting.
- **Status:** UNTESTED

  Symbols:

  - `___MIG_check__Request__exception_raise_state_identity_t`
  - `___MIG_check__Request__exception_raise_state_t`
  - `___MIG_check__Request__mach_exception_raise_state_identity_t`
  - `___MIG_check__Request__mach_exception_raise_state_t`

### libswiftCoreData.dylib

`@rpath/libswiftCoreData.dylib`

## Our own components (not shims for missing API)


### Siri Remote cursor (cursor/)

- **What:** A pointer overlay driven by the Siri Remote, turning a clickpad press into a tap on screens built for touch.
- **Evidence:** GCEventViewController.h:20 and :42 (tvOS SDK 27.2) for the focus-engine bypass and its exact condition; GCMicroGamepad.h:63 for the profile; GCController.h:50-72 for the lifecycle notifications; UIPress.h:26 and UIResponder.h:112 for Play/Pause.
- **Decision:** REDIRECT
- **Reason:** Roblox's menus have no focusable UIKit controls for the focus engine to drive, so without a pointer they cannot be used. Gameplay is left alone: the cursor hides itself when an extended gamepad appears.
- **Status:** UNTESTED
- **Private API used:** UITouch's _locationInWindow/_window/_view/_phase ivars, used only for click-to-tap preference 2 (delivering touches to the engine's render view). Every ivar is looked up with class_getInstanceVariable at runtime and the whole path is refused if any is absent, so an OS change degrades to "cursor cannot click this view" rather than crashing. Their presence on tvOS 27.2 is checked by the uitouch-ivars and uitouch-class queries in evidence/queries/device_queries.json. UNVERIFIED until that output lands.

### logging (tvlog/)

- **What:** os_log under subsystem tvport with categories shim/cursor/input/lifecycle/storage/crash, mirrored to a rotated file in Caches, plus a startup banner, per-shim first-call backtraces and call counts, and crash handlers.
- **Evidence:** Apple's tvOS guide states an app "can only access 500 KB of persistent storage that is local to the device (using the NSUserDefaults class)" and that "all other data must be purgeable by the operating system when space is low", so the file mirror is a convenience and os_log is the record.
- **Decision:** REDIRECT
- **Reason:** The device is the only place the UNTESTED statuses above can be settled, so the build has to say what it did. The signal handler is async-signal-safe (write(2) only, no malloc, no os_log, no stdio) and both it and the uncaught-exception handler chain to whatever was installed before, so the process still dies and tvOS still writes its own crash report.
- **Status:** UNTESTED

### platform identity (shim/platform_identity.m)

- **What:** UIDevice systemName/model/localizedModel/userInterfaceIdiom and UITraitCollection userInterfaceIdiom report iPadOS/iPad/UIUserInterfaceIdiomPad instead of tvOS/Apple TV/UIUserInterfaceIdiomTV.
- **Evidence:** tvOS returns UIUserInterfaceIdiomTV, an idiom Roblox's iPhone/iPad build never handles; iOS SDK 26.2 declares the types these getters return (recorded by the UIDevice-identity and UIUserInterfaceIdiom-enum targets in evidence/queries/ios_header_targets.json).
- **Decision:** REDIRECT
- **Reason:** Roblox's UI has no layouts, assets or code paths for the TV idiom, so whatever branch it selects is untested at best. Answering the way iPadOS would is a compatibility shim in the same sense as the rest of Phase 4. Swizzled rather than replaced, keeping the original IMP, so the log records the real tvOS value next to what was returned. Scope is deliberately local: it changes what UIKit answers inside this process, not Roblox's code, not its tamper checks and nothing server-facing. systemVersion is left truthful so crash reports stay useful, and Info.plist keeps UIDeviceFamily=[3]/AppleTVOS because tvOS will not install the app otherwise.
- **Status:** UNTESTED
